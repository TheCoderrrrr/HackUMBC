# Fund-aware retirement plans

ARM now models one confirmed target-date fund per profile. A manual profile records the catalog fund ID, account type, and the user's confirmation that the entered retirement balance is invested in that one fund. A 401(k) user may also confirm the fund is in their plan menu. The three fictional demo profiles carry reviewed BlackRock LifePath Class K funds and remain synthetic examples.

The server resolves the selection from `backend/app/data/fund_catalog.json`. Clients never submit a fee or glide path for calculation. For the BlackRock records, four numeric equity anchors documented in the reviewed prospectus drive a calendar-based glide path keyed to the fund's target year. The documented annual expense ratio is deducted from illustrative gross asset-class returns. The State Street records have no reviewed numeric anchors; those evaluations explicitly use the generic retirement-age glide path and say so. All evaluations include catalog version, share class, fee date, source links, glide-path mode, and limitations in `assumptions.fund_model`. With no selected fund, ARM uses the generic model and labels it.

Scenario requests may set an extra monthly debt budget in cents and a priority style. The budget is assigned by highest APR, cannot exceed available monthly cash while debt remains, and stops when debt is paid; automatic debt priority does not add more above the entered budget. The server returns 422 for an unaffordable budget. A `base_decision_id` pins a scenario to the live base decision for the same profile hash. A stale or missing ID requires refreshing the base plan. The expandable rules comparison reruns the same profile, fund and scenario with the default decision order, and labels equal outcomes explicitly.

The web app can save a manual profile under an anonymous key. iOS stores a local copy and saves to `/v1/profiles/me` when history is available, falling back to an unstored build when it is not. History saves recompute server-side, check the input hash, and persist the complete dated assumptions including the fund snapshot. Run summaries expose the fund name, catalog version and glide-path mode from that snapshot. Older saved runs retain their original model version and numbers; the new live model and freshly exported offline bundle use model and policy version `2.0.0`.

To refresh contracts and the offline bundle after a modeling change, update validated fixture decisions and their hash-keyed explanations, run `python scripts/export_contracts.py` and `python -m scripts.export_demo` from `backend/`, then copy `backend/fixtures/generated/*.json` into `ios/AdaptiveRetirement/Resources/Demo/`. The exported bundle is also loaded by the web app. Run `pytest backend/tests` from the repo root with `.venv/bin/python`.

Projection limits remain material: constant illustrative asset-class returns, no volatility or retirement withdrawals, and fixed debt APRs. A fund's past returns are not used as a forecast. ARM recommends how to use the entered fund alongside cash, debt and contributions; it does not place trades or recommend switching funds in scenarios.
